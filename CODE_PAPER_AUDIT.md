## Method checks

- The principal joint configuration resolves to top-50 GPU Monte Carlo PPR with restart probability 0.15; the preprocessing YAML specifies 100,000 walks and a maximum length of 86. The standard and compact models resolve to 16-dimensional Gaussian inputs, the stated GPS widths/layers, four heads, 0.1 dropout, SGFormer with two GNN layers, and decoders [128, 32] and [64, 16].
- The six structural targets, including the exact lengths 2, 3, and 4 CycleSE, are constructed on PPR-induced graphs. Root-level and graph-level heads use the appropriate root and mean-pooled states. Training-only target statistics pool valid coordinates within each target family.
- The source runners build embeddings from `G_train`; test evaluation builds embeddings and performs message passing on `G_train+val`. Negative candidates are filtered against the union of positive train, validation, and test edges. Test positives are excluded from the observed graph by the shared graph constructor.
- AP groups score ties at thresholds and ROC-AUC uses average ranks. The scaling aggregate uses a dataset macro within each task, then mean and sample standard deviation across three tasks.
- These checks establish intended code paths, not that the uploaded aggregate CSVs were actually generated by those paths. The archive has no raw run outputs with which to verify the history.

## Corrections in this reviewed copy

1. `configs/experiment_1a/one_dataset_gpu_mc_50.yaml`: the Link1 within-dataset configs inherited `approximate_push` from generic defaults even though `train_lppe_capacities.py` supplies GPU Monte Carlo PPR caches. The corrected parent YAML declares `gpu_monte_carlo`, 100,000 walks, 86 maximum steps, CUDA:0, seed 42, and its preprocessing protocol version. This changes resolved configuration hashes; existing checkpoint identities should retain their original config metadata, not be retroactively relabeled.
2. `src/zero_shot_gfm/preprocessing/pse_features.py`: the explicit Local PSE baseline formerly considered same-shaped cached shards and a same-shaped combined matrix reusable even after the PPR input manifest changed. It now requires matching manifest identity for reuse and rebuilds the combined matrix when any shard is rebuilt. A synthetic test changed the PPR fingerprint while keeping feature shape fixed and confirmed cache invalidation and regenerated values.
3. Removed an always-empty list computation in `scripts/run_experiment_2_task.py`, an unused LPPE output dataclass, an unused link-model registry, and an unused cycle canonicalizer. These removals do not change the model's forward path.

## Remaining limitations and cleanup

- `validate_lppe_cache_protocol()` checks `max_nodes`, graph fingerprints, and target fingerprints, but does not compare the cached PPR method, walk count, restart probability, or protocol version against the resolved training configuration. The within-dataset YAML correction makes the intended setting accurate, but a wrong method in an externally supplied cache can still be accepted if its size and graph fingerprint match. Add a full PPR-protocol comparison before claiming exact run-level matching.
- The generic `configs/base/defaults.yaml` describes a larger smoke model, approximate-push PPR, ranking metrics, and other options outside the reported final runs. Other alternate configs, ranking workflows, legacy scheduler APIs, and plotting utilities remain in the archive. Some support the experiments, while others are historical or optional. A blanket deletion would risk losing cache compatibility and alternative entry points; determine whether a minimal reproduction-only archive is required before pruning them.
- `README.md` provides an inventory but no end-to-end commands with a complete required cache and output path for every study. All reported experiments have code paths, but a third party must reconstruct the sequence and supply substantial compute and missing input data.
- Neither the global-method timeout evidence nor the published summary numbers can be independently checked without the omitted logs, per-target results, checkpoints, and AnyGraph data. The `pyproject.toml` declares PyTorch and PyG, but those packages are not installed here, so a full import, GPU run, or training verification was not possible.
